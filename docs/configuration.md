## Config directory layout & load priority

| File | Purpose |
|------|---------|
| `.env` | User-level config (`DATA_ROOT`, model, channel credentials, `GIT_PUSH`, `SCHEDULER_ENABLED`, `WEBUI_ENABLED`, `MONITOR_ENABLED`, etc.), permission `600` |
| `providers.json` | Custom model providers (OpenAI-completions / Anthropic-messages gateways): `api` / `baseUrl` / `apiKey` / `models` per provider |
| `system-prompt.md` | Externalized system prompt, supports `__DATA_ROOT__` / `__PROJECTS__` / `__PROJECT_CONTEXT__` / `__TODAY__` placeholders |
| `schedules.json` | Scheduled-task config; created via chat, WebUI, or hand-editing |
| `contacts.json` | Per-channel known-address store for push delivery (WeChat `context_token`s + recorded addresses) |
| `task-logs/` | Per-day JSONL task logs (consumed by the WebUI) |
| `wechat/account.json` | WeChat iLink login credentials (never commit) |

Config load priority (high to low):

```text
process env vars  >  ~/.botler-agent/.env  >  source .env (dev fallback)  >  built-in defaults
```

Set `BOTLER_CONFIG_DIR` in process env to override the `~/.botler-agent` location (useful for Docker `/config`, testing, or multiple profiles).

## Custom model providers (`providers.json`)

Custom OpenAI-completions / Anthropic-messages compatible gateways (self-hosted / internal endpoints, e.g. a self-hosted OpenAI-completions gateway or Volcengine Ark coding endpoint) are defined in `~/.botler-agent/providers.json` (generated by `botler init`). When the file is missing, legacy `CUSTOM_BASE_URL` / `CUSTOM_API_KEY` env vars work as a fallback.

`api` selects the wire protocol per provider: `"openai-completions"` (default) or `"anthropic-messages"`.

```json
{
  "providers": {
    "custom": {
      "api": "openai-completions",
      "baseUrl": "https://your-gateway.example.com/v1",
      "apiKey": "sk-…",
      "models": [
        { "id": "your-model-pro", "name": "Your Model Pro", "reasoning": true, "contextWindow": 1048576, "maxTokens": 393216, "vision": true },
        { "id": "your-model-flash", "name": "Your Model Flash", "reasoning": false, "contextWindow": 1048576, "maxTokens": 393216, "vision": true }
      ]
    },
    "ark": {
      "api": "anthropic-messages",
      "baseUrl": "https://ark.cn-beijing.volces.com/api/coding",
      "apiKey": "sk-…",
      "priority": 10,
      "model": "ark-code-latest",
      "models": [
        { "id": "ark-code-latest", "name": "…", "reasoning": false, "contextWindow": 524288, "maxTokens": 32768, "vision": false }
      ]
    }
  }
}
```

- **Select primary model**: set `PI_PROVIDER` to a provider id and `PI_MODEL` to one of its model ids in `.env`, then restart — the model is cached per process.
- **Built-in Anthropic**: set `PI_PROVIDER=anthropic` and authenticate via `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` (no `providers.json` entry needed).
- **Add a provider / model**: edit `providers.json` directly — no framework change needed. Malformed entries are skipped with a warning.
- **`api` protocol**: `"openai-completions"` (OpenAI Chat Completions, default) or `"anthropic-messages"` (Anthropic Messages API, appending `/v1/messages` to `baseUrl`).
- **Provider fallback chain (optional)**: set `"priority"` (integer, smaller = higher priority) and `"model"` (backup model id, required when `priority` is set) on backup provider entries to form an automatic runtime fallback chain behind `PI_PROVIDER` / `PI_MODEL`. Set `"fallback": false` to exclude an entry from acting as a backup. Providers without `priority` never join the fallback chain.
- **Model fields**:
  - `id`: model id sent to the gateway
  - `name`: display name
  - `reasoning`: whether thinking/reasoning is supported
  - `contextWindow` / `maxTokens`: context and max output token limits
  - `vision`: whether the model accepts image input (**defaults to `true`** when omitted). Only set `"vision": false` for text-only models — otherwise WeChat inbound images and vision tasks will be rejected.

## Customizing the system prompt (`system-prompt.md`)

`botler init` generates `~/.botler-agent/system-prompt.md`, which is re-read on every task (no restart needed):

1. Keep the four runtime placeholders intact: `__DATA_ROOT__`, `__PROJECTS__`, `__PROJECT_CONTEXT__`, and `__TODAY__`.
2. Customize global operating tone or shared rules, or ask an AI assistant to generate one tailored to your subprojects:

   > My botler-agent data directory has subprojects `notes/` (daily notes) and `vocab/` (word book). Write a `~/.botler-agent/system-prompt.md` following "read before write, keep JSON valid, keep field types consistent, report in Chinese after writing", keeping the `__DATA_ROOT__` / `__PROJECTS__` / `__PROJECT_CONTEXT__` / `__TODAY__` placeholders.

> **Security note**: allowlisted directories, controlled tools, and no arbitrary shell are enforced in code — prompt changes cannot bypass tool boundaries.

## Channels (Telegram / Feishu / WeChat)

- **Telegram** (long polling): simplest setup. Requires `TELEGRAM_BOT_TOKEN`; set `TG_PROXY` (e.g. `http://127.0.0.1:7890`) if Telegram API is blocked on your network. Set `TELEGRAM_ALLOW_FROM` (comma-separated user ids or usernames) to restrict senders; empty allows all.
- **Feishu** (event-subscription webhook with optional decryption): requires `FEISHU_APP_ID` / `FEISHU_APP_SECRET`; optional `FEISHU_VERIFICATION_TOKEN` / `FEISHU_ENCRYPT_KEY`; listens on `FEISHU_PORT` (default `3000`). Restrict senders with `FEISHU_ALLOW_FROM` (comma-separated `open_id`/`user_id`/`union_id` or chat ids).
- **WeChat (iLink / ClawBot official Bot API)**: DM channel. Run `botler wechat-login` first (prints a terminal QR code; scan with WeChat to save credentials to `~/.botler-agent/wechat/account.json`), then set `WECHAT_ENABLED=1`.
  - **Sender allowlist & renewal**: the QR-scanning owner is always allowed; `WECHAT_ALLOW_FROM` adds extra `ilink_user_id`s. `WECHAT_REMINDER_HOURS` (default `23`) nudges the owner before the 24h `context_token` window expires.
  - **Inbound images (vision + batching)**: inbound photos are fed to the model as vision input and saved under `DATA_ROOT/<project>/photos/`. Because WeChat sends a selected photo immediately while you may still be typing its caption ("选图即发，文字后到"), images wait briefly (`WECHAT_IMAGE_BATCH_SECONDS`, default `60`; `0` disables) so follow-up text and additional photos merge into a single task. If the active model has `vision: false`, the bot replies in Chinese asking for a short text description.
  - **Outbound images**: only WeChat delivers outbound images (`![](...)` inside `DATA_ROOT`); other channels strip image markdown and send text only.
- **Shared IM behaviors**:
  - **Greeting short-circuit**: bare greetings (e.g. `你好` / `hi`) skip the routing LLM call and return a zero-cost Chinese welcome listing available subprojects.
  - **Recent conversation & reset**: IM channels share a bounded recent-turn window (`CONVERSATION_CONTEXT_TURNS`, default `5`) for short follow-ups. Asking for a new task or context reset invokes `clear_conversation_context` to clear the window.

## Scheduler (`schedules.json`)

Set `SCHEDULER_ENABLED=1` to run the in-process scheduler. Entries can be managed from chat (via the `schedule` tool), the WebUI, or by editing `schedules.json` directly — saving immediately wakes the scheduler loop.

Each entry specifies **exactly one** trigger among `cron`, `interval`, `at`, or `once`:

```json
{
  "schedules": [
    {
      "id": "morning-water",
      "enabled": true,
      "cron": "0 8 * * *",
      "timezone": "Asia/Shanghai",
      "message": "提醒我该喝水了",
      "project": "my-project",
      "recipient": { "source": "wechat", "userId": "wxid_xxx" },
      "retry": { "max": 1, "backoffMs": 60000 },
      "silentHours": { "from": "23:00", "to": "07:00" }
    },
    {
      "id": "workday-standup",
      "enabled": true,
      "cron": "0 9,18 * * *",
      "timezone": "Asia/Shanghai",
      "message": "提醒我复盘今天的工作",
      "holidayMode": "workday",
      "recipient": { "source": "wechat", "userId": "wxid_xxx" }
    }
  ]
}
```

- **Triggers**:
  - `cron`: 5-field expression (`min hour day-of-month month day-of-week`).
  - `interval`: `"5m"` / `"2h"` / `"1d"` (minute granularity, wall-clock aligned).
  - `at`: daily `"HH:MM"` in `timezone`.
  - `once`: one-shot ISO 8601 datetime (`"2026-08-20T22:00:00+08:00"` or `"2026-08-20T14:00:00Z"`). Fires **exactly once**, then becomes inert; `silentHours` does **not** apply to `once`.
- **`timezone`**: IANA timezone (default `Asia/Shanghai`).
- **`message` & `project`**: `message` is dispatched through the normal pipeline; setting `project` to a valid subproject skips the routing LLM call.
- **`recipient` & fallback delivery**: when set, results are pushed via `deliver()` — primary channel first, then `telegram → feishu → wechat` across configured channels with recorded contacts (`contacts.json`).
- **`retry` & `silentHours`**: optional failure retry and do-not-disturb window (fires inside `silentHours` defer to window end).
- **`holidayMode: "workday"`**: China legal-workday gating for `cron` / `interval` / `at` (cannot combine with `once`). Fires only on statutory workdays — skips statutory holidays (法定假日) and includes makeup workdays (调休补班); cron date fields are ignored and only `hour:minute` is used. Calendar data is fetched at startup and every 24h from `BOTLER_HOLIDAY_API_URL` into `BOTLER_HOLIDAYS_FILE`, degrading to Mon–Fri on outage.
- **Chat routing**: messages about schedules (or containing 定时 / 提醒 / 日程) route to the virtual `__scheduler__` project; the `schedule` tool is available in all execution contexts.

## WebUI & Monitor

- **WebUI**: set `WEBUI_ENABLED=1` to start the task-log viewer on `WEBUI_HOST:WEBUI_PORT` (defaults to `127.0.0.1:8900`; Docker image defaults `WEBUI_HOST=0.0.0.0`). Reads per-day JSONL logs from `task-logs/` and includes a Monitor tab; the only write operation is deleting task logs.
- **Monitor**: runs by default on `127.0.0.1:MONITOR_PORT` (default `8899`; avoid `3000` and `8900`), exposing `/healthz` (JSON), `/metrics` (Prometheus text), and `/healthz/history` (trend samples). Set `MONITOR_ENABLED=0` to disable only the standalone scrape port without affecting the WebUI Monitor view.

## Task lifecycle & data conventions

1. **Receive & dedup**: channel calls `dispatch(text, { id, source, recipient })`; duplicate `id`s within 5 minutes are ignored (scheduler entries bypass dedup).
2. **Serial queue**: all tasks execute sequentially so concurrent messages never corrupt shared data files.
3. **Two-phase run (`route → execute`)**:
   - *Route*: lightweight prompt (`project name + 300-char summary`) picks a subproject or `__scheduler__` (single-project setups skip routing; ambiguous messages ask the user to clarify).
   - *Execute*: creates a fresh `Agent` with the selected subproject's root `AGENTS.md` (or `CLAUDE.md` / `CODEBUDDY.md`), bounded by `MAX_TOOL_TURNS`.
4. **Validate & self-heal**: write tasks validate all data JSON files. If `edit` broke JSON syntax, a fresh `Agent` runs once with a self-contained repair instruction; if still invalid, the task reports an error without committing.
5. **Git commit (+ push)**: `commitIfChanged()` commits any modified independent git repo under `DATA_ROOT` (`GIT_PUSH=1` pushes repos with unpushed commits; see [Docker git push](docker-git-push.md)).
6. **Task log**: every run appends a JSONL entry under `task-logs/` regardless of outcome.

## Environment variables

See [`.env.example`](../.env.example) for a copy-ready template.

| Variable | Description |
|----------|-------------|
| `DATA_ROOT` | Data root directory operated on by the agent (allowlist = its first-level non-hidden subdirs) |
| `BOTLER_CONFIG_DIR` | Override user-level config directory (default `~/.botler-agent`) |
| `PI_PROVIDER` | Primary provider id (`anthropic` or an id defined in `providers.json`) |
| `PI_MODEL` | Primary model id (e.g. `claude-sonnet-4-5` or `your-model-flash`) |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` | Built-in Anthropic auth (when `PI_PROVIDER=anthropic`) |
| `CUSTOM_BASE_URL` / `CUSTOM_API_KEY` | Legacy single-gateway fallback when `providers.json` is absent |
| `LLM_MAX_RETRIES` | Max retries on the same provider per LLM call, incl. mid-stream drops (`0` disables; default `2`) |
| `LLM_RETRY_BASE_MS` | Exponential backoff base delay in ms (`> 0`, default `1000`) |
| `LLM_RETRY_MAX_MS` | Single retry backoff cap in ms (`> 0`, default `15000`) |
| `LLM_RETRY_BUDGET_SECONDS` | Wall-clock retry budget across the provider chain per call (`0` = unlimited, default `0`; recommended `120` with fallbacks) |
| `LLM_REQUEST_TIMEOUT_SECONDS` | Per-attempt HTTP timeout in seconds (`0` = never time out, default `0`; recommended `600`) |
| `LLM_FALLBACK_ENABLED` | `=0` disables `providers.json` fallback chain and uses only `PI_PROVIDER` (default `1`) |
| `LLM_RETRY_NOTIFY` | User-visible retry notices on WeChat / Telegram: `fallback` (default, provider switches only), `all`, or `off` |
| `TELEGRAM_BOT_TOKEN` | Telegram BotFather token; empty disables Telegram |
| `TG_PROXY` | HTTP/HTTPS proxy for Telegram API (e.g. `http://127.0.0.1:7890`) |
| `TELEGRAM_ALLOW_FROM` | Optional comma-separated Telegram sender allowlist (user ids or usernames); empty = allow all |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | Feishu app credentials; empty disables Feishu |
| `FEISHU_VERIFICATION_TOKEN` | Optional Feishu event subscription verification token |
| `FEISHU_ENCRYPT_KEY` | Optional Feishu event encryption key (empty = plaintext events only) |
| `FEISHU_PORT` | Feishu webhook port (default `3000`) |
| `FEISHU_ALLOW_FROM` | Optional comma-separated Feishu sender allowlist (`open_id`/`user_id`/`union_id` or chat id); empty = allow all |
| `WECHAT_ENABLED` | `=1` starts the WeChat iLink channel (requires `botler wechat-login`) |
| `WECHAT_ALLOW_FROM` | Optional comma-separated extra `ilink_user_id` allowlist (owner always allowed) |
| `WECHAT_REMINDER_HOURS` | WeChat `context_token` renewal reminder threshold: `0`=off, `1`–`24` hours (default `23`) |
| `WECHAT_IMAGE_BATCH_SECONDS` | WeChat inbound-image batching window in seconds (`0` = dispatch immediately; default `60`) |
| `GIT_PUSH` | `=1` pushes repos with pending commits after write tasks (default `0`; see [docker-git-push.md](docker-git-push.md)) |
| `WEBUI_ENABLED` | `=1` starts the local task-log WebUI |
| `WEBUI_HOST` | WebUI bind address (default `127.0.0.1`; Docker image sets `0.0.0.0`) |
| `WEBUI_PORT` | WebUI port (default `8900`) |
| `BOTLER_LOG_DIR` | Task-log JSONL directory (default `~/.botler-agent/task-logs/`) |
| `MONITOR_ENABLED` | `!=0` enables standalone health/metrics server (default `1`; `=0` disables port only) |
| `MONITOR_PORT` | Health/metrics server port (default `8899`; avoid `3000` / `8900`) |
| `SCHEDULER_ENABLED` | `=1` starts the in-process scheduler |
| `BOTLER_SCHEDULES_FILE` | Schedule config file path (default `~/.botler-agent/schedules.json`) |
| `BOTLER_HOLIDAY_API_URL` | China holiday calendar URL template with `{year}` placeholder |
| `BOTLER_HOLIDAYS_FILE` | Cached holiday calendar file (default `~/.botler-agent/holidays.json`) |
| `MAX_TOOL_TURNS` | Max tool-call turns per task (default `20`) |
| `CONVERSATION_CONTEXT_ENABLED` | `=0` disables IM recent-conversation injection (default `1`) |
| `CONVERSATION_CONTEXT_TURNS` | Number of recent visible turns kept per IM session (`0` disables; default `5`) |
| `CONVERSATION_TURN_MAX_CHARS` | Max characters kept per stored user/assistant message (default `4000`) |
| `CONVERSATION_CONTEXT_MAX_CHARS` | Whole-window character cap for injected context; drops oldest turns first (default `12000`) |
